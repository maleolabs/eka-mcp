## [Unreleased]

### Fixed
- **MCP `new` false refusal discrimination (bug:mcp-new-false-refusal, maleolabs/eka-cli#28)** — the single schema-shaped refusal `new requires {"project": …}` conflated three distinct causes, making intermittent refusals (byte-identical retry succeeds) undiagnosable. The tool-argument boundary now discriminates: malformed/non-object arguments surface the sanitized decoder error (`requires valid JSON arguments: …` / `requires a JSON object argument (got string)` — the double-encoded-payload signature), a missing required field names WHICH field is absent, and an empty or wrong-typed field names the field. The required-field contract is declared ONCE in `toolRequiredFields` and DERIVED into both the advertised `inputSchema.required` arrays and the runtime validation (all 16 hardcoded arrays removed; a two-way test asserts schema == declaration == enforcement, so the reviewed-source `{type,id}` vs deployed `{project,namespace,type,id}` drift cannot recur). Every argument-shaped refusal logs one stderr diagnostics line — `eka-mcp param-refusal tool=<tool> args_bytes=<n> cause=<invalid_json|missing_field|empty_field|wrong_type|invalid_arg> field=<name>` — carrying the argument byte length (the client-side-truncation vs omission discriminator); stdout stays protocol-only. BEHAVIOR DELTA DISCLOSURE: `draft_list` and `sync_push` previously IGNORED malformed arguments silently (`_ = json.Unmarshal`) and `feedback_list` refused them inline without diagnostics; all three now refuse malformed/non-object arguments deterministically through the same logged path (accept/reject sets unchanged for well-formed input; optional-only tools still tolerate absent/null arguments). Version identification documented in README (release builds stamp the git tag via ldflags into `pack.Version`; plain source builds report the source literal — verified end-to-end against tag v1.2.0). Tests: refusal-cause discrimination table, ~4KB unicode-heavy content round-trip, schema==enforcement both directions, exact diagnostics-line format per cause, truncated-line upstream parse pin, optional-field type mismatch (`invalid_arg`), absent-arguments tolerance for optional-only tools. Gates green (`go build ./...`, `go vet ./...`, `gofmt -l .`, `go test ./...`).
- **MCP help disclosure (bug:mcp-help-subcommands-hidden, req:eka-mcp-production B1/B3)** — `eka-mcp` manifest now declares the full subcommand set for help disclosure: the `commands` array lists `mcp` (whole-binary proxy) plus `manifest`, `install`, `configure`, `serve` matching the actual `cmd/eka-mcp` subcommands. The B1 contract stays `v1` (additive). `eka mcp -h` disclosure is now provided by the eka-cli native stub (static list fallback) and the proxy help (disclosure suffix), so the surface is visible even when the plugin is not installed. Tests: manifest contains all four subcommands, help disclosure, proxy execution unaffected. Gates green.

### Added
- **Interactive serve banner (eka/ts:mcp-serve-banner-ux, req:eka-mcp-production)** — upgrade the `eka mcp` / `eka mcp serve` TTY notice to the eka CLI visual language: a unicode banner with section headers, `└──` tree glyphs and aligned key-value rows, implemented LOCALLY in eka-mcp (no eka-cli import). The banner is state-derived and deterministic (no timestamps): eka-mcp version (`pack.Version`), embedded pack identity (`eka-ai-skill-pack v1.0.1 (stable)` from `skills/manifest.yaml`), MCP protocol `2024-11-05`, transport `stdio · JSON-RPC 2.0 · newline-delimited`, workspace block (`EKA_HOME` path, `initialized` yes/no, project/repository counts — uninitialized renders deterministic `not initialized` hint `run 'eka project register' to create it`, never a crash), and capability counts (`tools` = 21, `resources` = 1 + skills + templates). Hints: `eka-mcp configure --target opencode --dir . --json   (or claude, codex)` and `press Ctrl-C`. Colors (ANSI SGR `38;5;75` Info/Accent, `38;5;245` Dim) only when stderr is a TTY (`NO_COLOR`/`TERM=dumb` honored), plain UTF-8 otherwise. Protocol safety preserved: notice is stderr-only, gated on `isatty.IsTerminal(os.Stdin.Fd())`; non-TTY/piped runs print zero bytes to stdout (JSON-RPC channel never corrupted, conformance 100%). Banner is computed after `eka.Open()` so workspace counts are live, with a deterministic fallback on startup failure. Tests: TTY gate, initialized vs uninitialized content, byte-determinism, color plain-byte separation. Gates green (`go build ./...`, `go vet ./...`, `go test ./...`).
- **MCP feedback tools (eka/ts:mcp-feedback-tool, req:eka-mcp-production revision 4 §8.2 decision 4 — feedback loop as MCP)** — three new MCP tools `feedback_new` / `feedback_list` / `feedback_publish` mirroring CLI `eka feedback new/list/publish` (ADR-026) exactly: `feedback_new` creates a local draft under `EKA_HOME/feedback` (YAML frontmatter + markdown body, `fbk-YYYYMMDD-slug` id with collision suffix, `0700`/`0600` permissions, per-type scaffold, auto-injected `eka_version`/`os`/`created`/`command`), `feedback_list` lists drafts/published deterministically (id descending, `eka-feedback-list-v1`, empty list is `[]`), `feedback_publish` files a draft as a GitHub issue on the fixed target repository (same engine as CLI `feedback.Publish` — same `issueToken` ldflags gate, same `IssueClient`, same `MarkPublished` atomic rewrite). Invariants preserved: feedback **never** enters the canonical store and never becomes a CKO — no CKO produced, meta-information outside the knowledge model. Publish constraints inherited unchanged: release-binary requirement enforced (`issue token not bundled — use a release binary`), missing/invalid token refuses deterministically naming remediation (401/403 → `publish failed: invalid token — use a release binary`, never raw HTTP error), token never appears in outputs/errors/logs. Error messages follow refusal-class policy (no internal paths, no store details — `SanitizeError` applied via `handleToolsCall` `isError:true`). Docs: `README.md` tool table 18→21, `skills/docs/mcp-boundary.md` new “Feedback (meta-information outside the knowledge model)” section with explicit invariant statement and §8.2 decision-4 cross-reference. Conformance suite extended: `tools/list` exact 21-tool order + inputSchema/description checks (`eka-feedback-new-v1`/`eka-feedback-list-v1`/`eka-feedback-publish-v1`, required fields), `tools/call` success + byte-determinism for each tool, malformed-arg fuzz (`feedback_new` null/empty/wrong types/array, `feedback_publish` missing id, `feedback_list` string/number/array), refusal cases (unauthenticated publish → token gate, invalid draft id → `unknown feedback`, already-published idempotent), capability-level sanitization checks, and `internal/eka` integration tests against real `EKA_HOME/feedback` (creation, scaffold, ordering, unauthenticated/invalid-token/already-published, token non-leakage, CKO non-creation). Internal package `internal/feedback` vendored from `eka-cli/feedback` (model/store/github/publish) — standalone, no store/workspace imports, preserves file format and publish path. Gates green (`go build ./...`, `go vet ./...`, `go test ./...`).
- **MCP assignment tools (td:mcp-assignment-tools, req:eka-mcp-production §8.2 decision 3 — assignment write tools)** — three new MCP write tools `assign` / `reassign` / `unassign` mirroring CLI semantics exactly: same target forms (`<type>:<id>` or `<ns>/<type>:<id>` for the work item, `<mbr-id>` / `mbr:<id>` / `mbr-<id>` / `<ns>/mbr:<id>` for the member), same validation (work-item gate, namespace ownership gate, member resolvability with repository-scoped member list, cross-repository refusal, legacy Markdown draft refusal, missing-artifact refusal), same refusal classes and no partial writes (single-assignee ADR-029: `assign` refuses an already-assigned item with reassign hint, `reassign` refuses an unassigned item with assign hint, `unassign` is idempotent no-op). Every write sets explicit agent author identity (`AuthorIdentity{Kind:"agent", Name:"mcp-agent"}` default, never the Engineering placeholder) via `resolveAuthor` — `by`/`byKind` default to `agent` and `byKind` is validated deterministically. Output: `eka-assignment-v1` (`ok`, `action`, `item`, `assignee`/`no-assignee`, `state` ∈ published/draft/unchanged, `objectHash`, `by`). Engine: `assign` delegates to `runtime.Authoring.Relate` (no-churn re-point), `reassign`/`unassign` mirror the CLI's store re-point with same-version `RepointUnit` + CKO validation + draft mutation (`rewriteDraftAssignment`) + post-mutation `ValidateDraft`; CKO validation failures and store errors refuse with no partial write. Docs: `README.md` tool table 15→18, `skills/docs/mcp-boundary.md` new “Assignment (team-collaboration)” section with §8 matrix decision-3 cross-reference. Conformance suite extended: `tools/list` exact 18-tool order + inputSchema/description checks (eka-assignment-v1, required fields), `tools/call` success + byte-determinism for each tool, missing-arg and unknown `byKind` refusals (`isError:true`), capability-level refusal with sanitized text, and `internal/eka` integration tests against a real store (assign no-churn, idempotent same-target, different-target refusal, reassign single-operation move, unassign removal, no-op, member resolvability, non-work-item gate). Fuzz: malformed JSON / wrong-type / null / array args for assignment tools exercise the hardened `handleToolsCall` path (0 crash, 0 hang, deterministic `isError`). Gates green (`go build ./...`, `go vet ./...`, `go test ./...`).
- **MCP `sync_push` tool (ts:mcp-sync-push-tool, req:eka-mcp-production §8.2 decision 1 — push-only sync surface)** — new MCP write tool `sync_push` mirroring CLI `eka sync push` semantics exactly: same Authoring API path (`Authoring.Sync` with `Push:true`, `Pull:false`), same snapshot compilation (`exchange.EmitSource`), same digest (`SnapshotFingerprint`), same refusal classes; crash-safe atomic swap (`exchangeDir/.snapshots-tmp` staged then swapped) so a failed push writes nothing partially. Input: optional `repoPath` (default `.`), `adopt` (ADR-032 `--adopt`), `override` (ADR-020 `--override`); output: `eka-sync-push-result-v1` (`workspace`, `project`, `repo`, `pushedUnits`, `pushedAttachments`, `snapshotLabel`, `snapshotDigest`, `changed`, `newRepo`, `warnings` — byte-deterministic for identical store state). Pull / `--from-docs` re-seed is not exposed — any `fromDocs`/`from_docs`/`from-docs`/`pull` argument refuses deterministically naming the CLI `eka sync pull` as the sanctioned operator-supervised path (silent regression hazard — older instances can re-point line references). Unknown tool `sync_pull` is `-32003`. Docs: `README.md` tool table 14→15, `skills/docs/mcp-boundary.md` new “Runtime transport (sync)” section with the hazard rationale and §8 matrix cross-reference. Conformance suite extended: `tools/list` exact 15-tool order + `sync_push` inputSchema/description checks, `tools/call` push success + byte-determinism, pull-refusal fuzz, unknown-repo sanitized error (no `<path>` leak), and protocol `-32003` for `sync_pull`. Server hardening: error sanitization (no paths/stack traces) applied uniformly. Gates green (`go build ./...`, `go vet ./...`, `go test ./...`).
- **MCP error fidelity (sto:mcp-error-fidelity)** — structured authoring refusals now carry full fidelity across the MCP boundary without CLI fallback: publish/relate validation refusals (`*runtime.PublishError`, `*runtime.RelateValidationError`) embed the complete `eka-conformance-report-v1` as a second text content block (per-finding rule/severity/message, warnings included, deterministic order, path-redacted at serialization), transition membership-gate refusals surface the deterministic warning plus the explicit `retry with confirmed:true` affordance. The sanitized headline (block 0 = `SanitizeError`) stays byte-stable. Assignment validation (`assign`/`reassign`/`unassign` via `RelateValidationError`/`assignmentValidationError`) now uses `wrapValidationRefusal` to preserve the count-only headline verbatim while carrying the report (previously count-only dead code never reached `wrapToolRefusal`). `wrapToolRefusal` adds a double-wrap guard (`errors.As` → already `*toolRefusal` returns directly). Boundary guard hardens report embedding: `RedactPaths` result is validated with `json.Valid`; on invalid JSON the report block is dropped (no leak, no corrupt payload) and the false invariant comment about never crossing JSON string boundaries is corrected. Skill doc `eka-troubleshooting` scopes the self-contained claim to `publish/assignment and transition refusals`. Tests: boundary negative case with `at /home/u/x.db" done` escaped inside a finding message, assign-report end-to-end via `fakeCapability`, transition affordance stubs for warning-only and confirmation-only branches (covering `b.Len()==0`), and unit tests for `wrapValidationRefusal` and double-wrap idempotence. Gates green.

### Changed
- **MCP `view` → `draft_read` rename with deprecated alias (td:mcp-view-naming-fix, req:eka-mcp-production §8.2 decision 2)** — MCP draft-file reader renamed `view` → `draft_read` (same verbatim v2.0 JSON authoring document, deterministic). Old name `view` remains functional for one minor version after 1.1.3, flagged deprecated in `tools/list` description with migration note naming `draft_read`; conformance tests cover both names during the window; removal tracked via code TODO comments (server `handleToolsList` + `callTool` alias case and `Capability.View` wrapper). Docs updated wherever the draft-reader tool is referenced (`README.md` tool table, `skills/docs/mcp-boundary.md`) with explicit statement that human projections (`eka view`/`eka watch`) remain CLI-only and are not exposed as MCP tools/resources.
- **Skill-pack assignment coverage + patch bump** — `skills/manifest.yaml` pack.version `1.0.0` → `1.0.1` (bumpPolicy: command-surface references changed). `eka-engineering-workflow` now teaches the assignment operations (`eka assign` / `eka reassign` / `eka unassign`) at the execution loop's item-intake step: semantics, valid targets and states, deterministic refusal cases, and the membership clarification (tickets remain the sole container-membership contract — assignment never creates membership). `eka-knowledge-modification` gains the assignment-edge change path (no-churn edge writes, distinct from transitions and revisions). MCP assignment tools are marked pending — the server exposes no assignment tools today; the CLI is the only assignment surface.
- **BREAKING: `eka-mcp configure` decoupling (sto:mcp-configure-decoupling)** — `configure` now **only writes the MCP client config** by default; skill/command installation is opt-in via `--with-skills`, `--with-commands`, or `--with-all` (`--with-all` = both). Previously it always delegated `pack.Install("skills")` + `pack.Install("commands")`. Old callers (`eka-mcp configure --target opencode --dir . --json`) now get an `installed` field that is absent/empty unless opted in. Skills and templates remain accessible via MCP resources `eka://skills/*` and `eka://templates/*` without any file copy. `--dry-run` reflects only the opted-in plan and still touches no filesystem. Existing `--target opencode|claude|codex`, `--dir`, `--dry-run`, `--json` flags are unchanged. The write remains idempotent and merges without overwriting other servers.
